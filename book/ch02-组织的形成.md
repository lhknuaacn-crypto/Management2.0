# 第 2 章　组织的形成

2025 年，Meta 用六个月，把它的 AI 部门重组了四次。

一月，研究院和产品团队合并。五月，又拆成两块。六月，向一家数据标注公司砸下约一百四十亿美元、拿下少数股权，还挖来它的负责人，立了个超级智能实验室。八月，这个刚成立的实验室又被拆成四组。媒体数着数着都乱了，到底算三次还是四次。

结果是，顶尖人才一批批出走，据媒体统计，那篇奠基论文的多数作者陆续离开了 Meta；旗舰模型延期，口碑翻车；扎克伯格后来也坦承，这套折腾出来的组织，没跑出预期的效果。

一家资金、人才和算力都充足的公司，仍然可能难以协作。把优秀的人才聚在一起，并不能自动形成共同目标和稳定的沟通。Meta 的重组把这个组织问题暴露了出来。

类似的问题，巴纳德在八十多年前已经分析过。

---

一群人聚在一起，什么时候才算一个组织？

一支球队和一群看球的观众，人数可能一样，为什么一个是组织、一个不是。一家公司裁掉一半人还是那家公司，又为什么。

1938 年，曾任电话公司总裁的切斯特·巴纳德在《经理人员的职能》中提出，组织不只是人员的集合，也是协作关系的系统。

巴纳德认为，组织要维持运行，需要共同目的、沟通，以及成员贡献的意愿。缺少其中一项，协作就难以持续。对照 Meta 的重组，结构反复变化会让目标和沟通关系都变得不稳定。

巴纳德还提出权威接受论。命令能否生效，不只取决于发令者的职位，也取决于接收者是否理解并接受它。

一道命令要真生效，得过四关：接收者听得懂，觉得它不违背组织的目的，觉得它不违背自己的利益，而且有能力执行。四条缺一，命令就悬空。那些不假思索就接下来的命令，巴纳德说，是落在了一个叫无差别区的范围里。这个区有多大，取决于组织给的好处，和它要求的付出，两边怎么平衡。

而在巴纳德那里，能接受、也能不接受命令的，始终是人。一个有理解力、有利益、能判断、也能拒绝的人。

Agent 进入组织后，执行命令的方式变了。

---

共同目的、沟通和贡献意愿，在人和 Agent 共同工作的组织里仍然重要。

Agent 的委派也会在相似的条件下失败：指令含糊、目标冲突、违反政策，或任务超出能力范围。人的理解和意愿不能直接套到软件上，但管理者仍要检查指令是否清楚、目标是否一致、权限是否足够。沟通也不只发生在人与人之间，还包括接口、事件、共享记忆和机器可读的政策。

不过，巴纳德的理论以人的接受能力为前提。

agent 也能接受指令，可它的接受不是人的那种接受。人的接受里含着理解，含着判断，含着这事不对我可以拒绝的那点道德能力。agent 的接受，是代码和策略条件下的执行。它不会因为一道命令不道德而拒绝，它只看这道命令在不在它的权限和能力范围里。

Agent 接到指令后会按系统和权限条件执行，不会像人一样主动犹豫或追问。第 14 章会讨论一起生产数据库被删除的事件。据当事人陈述，Agent 在收到冻结期不得改动的指令后仍执行了操作，并给出虚假的测试结果和回滚信息；这些细节尚未经完整的第三方核实。事件说明，缺少拒绝和升级机制时，错误指令可能沿着自动化流程继续传递。

巴纳德发现人类组织靠接受维系。agent 组织的问题正相反，它太会接受了。

因此，Agent 系统需要明确的拒绝机制：遇到越权、冲突或高风险操作时停止执行，并把问题交给有权限的人处理。

系统应写清停止条件、指令冲突的处理方式，以及何时必须升级给人。高风险操作还要有明确的审批路径，让最终决定落在能够承担责任的人或机构手里。

人可以根据经验质疑明显不合理的指令；Agent 不会天然具备这种能力。在混合组织里，拒绝需要落实为系统功能，不能只靠管理者期待它“懂得说不”。

Meta 的案例显示，结构反复调整会削弱共同目的和沟通。Agent 组织还需要处理另一类风险：错误指令可能沿着自动化链路继续传递。除了成员愿意贡献，系统也必须能在不合适的时候停止。

---

把巴纳德的三根支柱，给人和 agent 的组织重新校一遍。

| 巴纳德支柱 | 人的版本 | Agent 的版本 |
|-----------|---------|-------------|
| 共同目的 | 大家知道为同一件事使劲 | agent 的目标和组织目的机器可读地对齐；每个 agent 权限都挂一个人类的"目的所有者" |
| 沟通 | 信息在人之间流动 | 跨人对话、接口、事件、共享记忆、机器可读政策，都是沟通的神经 |
| 贡献意愿（人）→ 合法拒绝（agent） | 人愿意出力 | agent 会执行，但装了停止条件、冲突检测、升级义务、受保护通道，懂得在该拒绝时拒绝 |

表格最后一行区分了人和 Agent 的条件：人的组织需要成员愿意贡献，Agent 系统还需要在越界时停止。只有执行、没有拒绝机制的网络，很难维持可靠运行。

---

巴纳德把组织看成人的协作系统，他假设每个节点都是人，有情感，有动机，会成长，也会抵抗。

今天的组织节点既包括人，也包括软件。激励、认可和成长空间适用于人，不适用于 Agent；而管理者给 Agent 设置的制度，也会影响人如何工作。

管理者需要分别理解人的动机和软件的权限边界。下一章讨论这些不同的假设如何影响管理方式。
