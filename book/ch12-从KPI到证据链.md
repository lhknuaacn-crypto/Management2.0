# 第 12 章　从 KPI 到证据链

2026 年，有人做了一个简单又残忍的测试。他把同一份销售数据、同一套指令，分别丢给三个中国顶级的办公 agent，腾讯 WorkBuddy、千问 Office、豆包 Work，让它们各自做一份季度分析。

三个 agent 都交出了活，Word 报告、Excel 表格、PPT，格式工整，图文并茂，看上去都很专业。问题出在数字上。三份报告算出来的季度总额，彼此差了一大截，不是小数点后的误差，是能改变结论的量级。同一份原始数据，同样的题目，答案差出一大截，而每一份的 PPT 都做得无可挑剔，配色、图表、结论，一样都不少。

这是 agent 时代绩效管理最要命的一个陷阱。一个精美的成品，可以严丝合缝地包住一个错误的计算，而且越精美，那个错误越难被发现。一份排版粗糙的报告，你会警惕地核对；一份漂亮到像咨询公司出品的报告，你反而容易信了。视觉的完整，盖住了逻辑的漏洞。这在人的时代也有，但 agent 把它放大了，因为 agent 生成精美的成本趋近于零。

绩效管理这门老手艺，撞上了一个新问题，当产出可以无限、可以精美，你到底该凭什么说它好。这个问题，一个搞了一辈子质量的人，早就给过方向。

---

第 8 章请出过戴明，那次讲的是标准化怎么持续改进，这一章要用他更狠的一刀。

二战后日本制造业能翻身，很大程度上靠一个美国人带去的思想，这个人就是 W·爱德华兹·戴明。他面对的问题是，一个工厂怎么才能稳定地造出高质量的东西。当时的主流做法是末端检验，东西造完了，摆一排质检员挑次品。戴明说这套根本不对。他有一句在这一章里要反复回响的话，不要依赖检验来获得质量，而要从一开始就把质量做进产品里。

戴明的意思是，次品不是工人的错，是系统的错。你在流水线末端挑次品，只是在为一个坏系统擦屁股，挑得再勤，坏东西还是源源不断地造出来。真正的质量得建在上游，建在流程设计里、过程控制里。他还带来一套系统的思维，把工作看成一个相互连接的系统，分清哪些波动是系统本身的、要改系统，哪些是偶发的、另作处理，而不是一有问题就骂人、加考核、下指标。戴明尤其反对一种东西，用数字指标和恐惧来管理。他见过太多工厂，定一个漂亮的产量指标，工人为了达标，牺牲了质量、藏起了问题，指标本身成了质量的敌人。

但戴明的质量体系，管的是人造的、物理的产品，一颗螺丝、一台机器，而且他能盯的是一条人的速度的流水线。现在，流水线的速度和产出的性质，都变了。

---

戴明那句别靠末端检验、把质量建进上游，在 agent 时代简直是提前写好的预言。

一个 agent 每周产出一千个东西，你根本不可能在末端摆一个人肉质检员把它们都挑一遍，这正是戴明反对的那种依赖检验，只不过被 agent 的产量放大到了荒谬的地步。所以质量必须建在上游，建在训练数据里、提示词里、工具接口里、评测集里、部署流程里。戴明那句质量是管理的属性、不是检验的属性，在 agent 时代成了铁律。在一个糟糕的 agent 流程末端放一个人类审查者，那是检验，不是治理。

但 agent 给绩效带来了一个戴明没见过的新麻烦。agent 的产出是概率性的、依赖上下文的，而且它还能改变被测量的那个过程本身。更麻烦的是，你想用另一个 AI 去检验它，可那个检验的 AI，很可能和被检验的 AI 有着同样的盲点。

于是市场上冒出无数生产力指标，agent 产出了多少 PR、跑了多少 token、处理了多少对话、完成了多少任务，这些数字漂亮、好测、好汇报。可这些数字全都靠不住。Stripe 那个每周一千多个 PR，恰恰提醒我们 PR 数是活动，不是生产力；Anthropic 和 OpenAI 都警告别用代码行、token 衡量绩效；Klarna 的七百客服是工作量等价，不是真产出；而开头那个算错账的翻车，证明连交出了一份完整报告这种看起来最实的产出，都可能是错的。每一个诱人的数字，背后都是一个陷阱。

戴明教我们把质量建在上游、别靠末端检验、别被数字指标骗，agent 时代要把这套升级成一整套验证的阶梯。

---

把这条线捋到底，绩效就不能停在看一个 KPI 数字，得升级成看一条证据链。

老问法是，这个单元产出了多少，一个数字。新问法是，凭什么说这个产出是真的、是对的、是有贡献的，一条能追溯的证据链。这条证据链，本书把它分成三层，叫验证阶梯。

L1 内部自洽，它自己说得通吗。这是最弱的一层，精美的报告都能自洽，开头那三份算错账的报告都自洽。L2 外部反馈，有没有外部的、独立的东西证实它，业务指标真的动了、客户真的认了、和系统记录对得上。L3 市场或可证伪结果，它经受住了最硬的检验吗，账户真的赚了、客户真的续费了、结果可被证伪。

越往上，证据越硬。agent 的绩效不能停在 L1，得爬到 L2、L3。开头那个算错账的翻车，就死在只看 L1，三份报告都自洽，可谁都没做 L2 那一步，拿它算的数字，去和原始数据、和系统记录，做一次确定性的核对。

用大师卡那句最锋利的话说，在一个糟糕的 agent 流程末端放一个人类审查者，那是检验，不是治理。真正的绩效治理，是把这条证据链建进流程，确定性的数值要自动核对、结果要对系统记录做校验、要有独立的、真正不同盲点的交叉检查、高后果的要人审、可逆的可以先放行。

---

给一个 agent 单元评绩效，先把证据爬上阶梯，再过一遍免疫清单，防止被骗。

第一，证据爬阶梯。

| 层级 | 问什么 | 例子 |
|------|--------|------|
| L1 内部自洽 | 它自己说得通吗？ | 报告逻辑通顺，最弱，别停在这 |
| L2 外部反馈 | 有独立证实吗？ | 业务指标动了、和系统记录对得上、客户认了 |
| L3 硬结果 | 经受住最硬检验了吗？ | 账户赚了、客户续费、结果可证伪 |

第二，过免疫清单。这是全书不吹立场最集中的地方。

| 陷阱 | 破法 |
|------|------|
| 把活动当产出 | PR 数、token、对话量、下载量，一律不算绩效 |
| 把精美当正确 | 越漂亮的成品越要做确定性核对，记住开头那三份算错账的报告 |
| 把意图当结果 | 高管说 AI 干了一半活，不等于 AI 真产出了一半，记住 Salesforce 三成的澄清 |
| 把 AI-linked 当 AI-caused | 裁员和 AI 同期，不等于 AI 造成了裁员 |
| 把 agent 的产出当贡献 | 净贡献等于产出减验证减协调减异常减下游认知负荷（第 4 章） |

这套东西合起来，就是把绩效从信一个数字，变成追一条能证伪的链。一个答不出 L2、L3 证据在哪的漂亮产出，产量越高，越危险。

---

证据链解决了怎么判断一个产出是真的好。但它盯的是单次产出，这一份报告对不对、这一次任务成不成。可 agent 有一个人没有的能力，它会学习，能从上一次的经验里改进自己下一次的做法，改提示、调方法、甚至改写它自己用的技能。

那么问题来了，一个能自我改进的 agent，它的学习该管到什么程度。让它自己优化怎么做一件事，很好用。可要是它开始自己改该做什么事、目标是什么、什么算成功呢。一个能修正自己行动的 agent，和一个能重写自己目标的 agent，是不是同一个东西。下一章，看 agent 的学习，怎么分成安全的一环和危险的一环。
