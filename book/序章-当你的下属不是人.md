# 序章　当你的下属不是人

人类很早就学会了分工。因为一个人盖不起一座城，也治不了一条河，于是有了号令，有了层级，有了记事的账。这些都是管理学要解决的问题，虽然这门学科岁数不大，满打满算一百多年，可它要对付的难题，却和金字塔、和都江堰一样老。

这一百年里，管理换过许多说法，但是本质没变过：干活的是人。泰勒算的是人的动作，法约尔理的是人的层级，德鲁克提振的是人的心气。他们的理论，看起来各有所长，唯独在这一点上保持一致——执行的是人，会累，会误会，会偷懒，也会在要紧关头顶上去。所有的办法，都是照着这样一种人想出来的。

最近这 36 个月，管理学面对的执行者开始变了。

先举例。凌晨三点一家公司的账上，一笔钱的去向被挑了出来——数目、时点、对手方，都有些不对。这个时间没有人醒着。挑出它的是一段不睡觉的程序，可接下来的事，就不太像程序了。它没有报警，而是叫起了另外几段同类：一段去翻这家对手两年的往来，一段去对合同和这笔钱对不对得上，一段去查这条审批线上每一步是谁点的头。它们各跑各的，又把结果凑到一处，先排掉三种看着可疑其实寻常的情形，剩下一种，连同一条来龙去脉，搁进了一个人的待办里。

天亮，负责这件事的那人端着咖啡坐下，看完这份东西，做了个决定：先冻结，转法务。然后他喝完咖啡，开始这一天。

昨夜那台机器里的事，没办法用过去的分类方式来归类。说它是自动化，它却不照一条写死的规则走，它自己有判断力，能判断该叫谁、该查哪、该舍什么。说它是软件，它却有分工，有交接，有拿不准就往上递的分寸感，像一个审计团队的调查组。说它是一个组织，也行，只是这组织里除了清晨那个做决定的人，没有一个成员是人。

过去的管理学经典里，还找不到完全一样的案例。它是新出现的。

我想拿一百年来管理学留下的问题，重新看一遍这个变化。

先说明一个最重要的原则：人没有被取代。昨夜那件事里，那个冻结、转法务的决定，还是人做的。变的不是人在不在，是经理管的那个单位，换了形状。以前他管一个人，或者一群人。而现在，他管的是：一个人，加一队会自己动手、自己商量、自己往下推、只在要紧处才回头问一句的伙计。而这些伙计，不是人，是 Agent。


影响不只在工具上。管理学从工具到概念，都是围绕人的工作形成的。现在，组织里出现了非人类的执行者。目标、分工、授权、绩效、责任，这些用了百年的词，还能不能原样解释新的工作？

本书会带着管理学走进人和机器共同工作的组织，逐个检查这些概念哪些仍然适用，哪些需要修改。

泰勒、法约尔、韦伯、德鲁克、明茨伯格、戴明、科斯，各自在当时回应了真实的组织难题。他们留下的许多答案今天仍然成立。Agent 进入公司后，执行者的构成变了，旧理论的适用范围也需要重新检验。本书从已经发生的技术和组织实践出发，讨论这些变化带来的管理问题。

本书主要讨论正在发生的变化，尽量用公司里的实际案例来检验判断，不把对未来的猜测当成结论。

Stripe 的编码程序每周能生成一千多份代码改动。这个数字记录的是活动量，不能单独说明产出价值。每份改动仍要有人阅读、核验和决定是否合并。机器生成内容的成本降下来后，人的验证时间就成了限制因素之一。全书会反复讨论这个变化：执行更便宜了，验证、判断和责任仍要由组织承担。

关于 AI 的讨论常在价值和风险之间摆动。本书更关心公司里已经发生了什么。Salesforce 的马克·贝尼奥夫先说 AI 承担了公司三到五成的工作，后来澄清，工程领域的生产力提升约为三成，工程师仍然不可缺少。Klarna 曾以“相当于 700 名客服的工作量”描述 AI 服务，后来又承认，单看成本会损害服务质量。Anthropic 对内部员工的研究也记录了另一面：有人更多向 Claude 提问，较少向同事求助；一些员工担心自己的技能在退化。这些案例提醒我们，工作量、服务质量和员工成长不能用同一个数字衡量。

这本书分四部。

第一部回到管理学的起点，讨论工作规模超过个人能力之后，人们怎样协作。

第二部讨论 Agent 的不同形态：个人助手、应用内副驾、流程执行者和多 Agent 队伍。形态不同，所需的管理方式也不同。

第三部讨论人和 Agent 共同工作的组织，并以法约尔的管理职能为线索，展开计划、组织、授权、运行、验证和进化六个环节。对 Agent，管理者需要设定权限和边界，不能照搬对人的指挥方式。

第四部讨论两件事：Agent 如何改变公司的边界；当执行工作逐渐自动化后，哪些决定和责任仍须由人承担。

全书最后回到人的责任：当机器承担更多建造和执行工作，哪些决定、关系与后果仍须由人负责。

我们就从凌晨三点那个做决定的人说起。不过在那之前，先回到一百年前，看看管理这套做法，最初是如何被人逐步摸索出来的。
