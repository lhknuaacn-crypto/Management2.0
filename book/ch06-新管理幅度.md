# 第 6 章　新管理幅度

管理学里有一个用了几十年的数字：一个经理能有效管的下属，大约五到七个。这叫管理幅度。超过这个数，他就顾不过来，开不完的一对一、对不齐的信息、漏掉的问题。军队按这个数编班排，公司按这个数画组织架构图。

现在把这个数字扔进 agent 时代。

一个反复被从业者提到的经验是，让一个工程师同时指挥一堆能自己干活的编码 agent，很快就会撞到一堵墙，大多数人最多同时盯得住三五个高交互的 agent 会话。再多，他就开始跟丢，这个卡在哪了、那个要不要批准、哪个已经跑偏。有人形容得传神，这就像给你一群能干的初级工程师，然后逼一个资深工程师去微观管理他们，很快就管崩了。这个三五个是从业者的经验，不是哪个公开实验的定论；学界研究一个人能盯几个自主系统，结论也一致，这个上限随任务耦合度、打断频率、agent 自治度而变，没有一个放之四海的固定数。

三到五个。这个经验值，和明茨伯格那个五到七个人，近得让人起疑。难道 agent 再强，一个人能带的还是就这么几个。那"AI 让一个人顶一个团队"的说法又怎么讲。问题出在我们还在用带几个这把旧尺子，量一件已经变了形的事。

---

要谈经理到底在管什么，绕不开亨利·明茨伯格。

1973 年，管理学界还信着法约尔那套，经理的工作就是计划、组织、协调、控制，一个坐在办公室里冷静运筹的人。明茨伯格干了件很朴素的事，他跑去真实地跟着经理们，看他们一整天到底在干嘛。

结果和教科书对不上。真实的经理一天被切成无数碎片，接电话、被打断、开短会、临时救火、来回沟通。没有哪个经理在冷静运筹，他们在高频、琐碎、口头、被打断地处理一件又一件事。明茨伯格有句话戳破了这层窗户纸，你问经理们干什么，他们会说计划、组织、协调、控制，然后你去看他们真正在干什么。

他的贡献，是把经理这个抽象职位，拆成了十个具体角色，分三类。人际类，挂名头领、领导者、联络人。信息类，监测者、传播者、发言人。决策类，企业家、危机处理者、资源分配者、谈判者。而且他发现这十个角色是咬在一起的一台机器，正式权力带来人际关系，人际关系带来信息，信息支撑决策，抽掉哪一环，后面的都塌。

但明茨伯格观察的那个经理，管的是人。他那十个角色，全都默认下属是有理解力、有判断、会自己补位的人。现在，经理的下属里混进了不是人的东西。

---

明茨伯格那十个角色，恰好是一张绝好的地图，用来分清哪些管理动作能交给 agent，哪些必须人自己留着。

agent 能干不少角色里的活。它能当监测者，盯着比一个人能盯的多得多的信号；能当传播者，把信息分发出去；能当发言人对外输出；能按规则做资源分配；能在边界内谈判；能处理例行的危机。明茨伯格的十角色，第一次可以被拆开，分给人和 agent。他的框架照样好用，只是使用者从一个经理，变成了人和 agent 一起。

但拆开之后，冒出一个明茨伯格没有的新麻烦。

Agent Harness 让 agent 能持续、并发地跑。你不再是跟一个 AI 对话，而是同时挂着一堆 agent 会话，每个都在自己往前推。于是有了 Grok Bot 这种东西，一支看得见的队伍，一堆命名的、分了角色的 Bot，并行干活、互相交接。管的对象从一个 agent 变成了一队 agent。

而一队 agent 撞上的墙，就是开头那个经验，一个人最多盯得住三五个高交互的 agent。这墙不是模型不行，是人的注意力不行。你带的不再是人数，而是同时要盯的自主回路数，每条回路都可能卡住、跑偏、要你批准。

管理幅度因此要重新定义。它不再是下属人数，而是可安全监督的自主执行回路数。一个人能带一百个 agent 吗，能，前提是这一百个大部分时候不用他盯，它们跑在有界的、可自动验证的回路里，只在真正需要判断的关口才升级给他。一个人只能带三个 agent 吗，也对，如果这三个每个都在做高风险、需要连续盯防的活。决定管理幅度的，是每条回路要占用多少人的注意力。

---

把明茨伯格的十角色和这条线拼起来，新原则就清楚了。

agent 能扮演几乎每一个管理角色，能当发言人、能分配资源、能处理危机。可能扮演，不等于有资格扮演。一个模型可以像发言人一样对外说话，却没有代表公司做承诺的权力；可以像资源分配者一样调度，却不懂调度背后的政治后果。

所以要把角色能力和角色授权分开。一个 agent 能干某个角色的活，是能力问题；它有没有资格替组织在这个角色上做出承诺，是授权问题。两者必须分开定义。

每一个交给 agent 的角色，都得配四样东西。一个明确的授权级别，它能自己做到哪、哪里必须停。一个身份信号，让人和系统知道现在在跟一个 agent 打交道、它有多大权。一条承诺边界，它能替组织承诺什么、不能承诺什么。一个人类回接点，超出边界时权力交回给谁。

用大师卡那句最狠的话说，agent 几乎能扮演每一个管理角色，这不意味着它该继承经理的职位。

明茨伯格的十角色，因此从一个经理身上的十顶帽子，变成了一张人机分工表，哪些帽子给人、哪些给 agent、哪些人机共戴，每一顶都标清能力和授权。管理者的活儿，从戴好这十顶帽子，变成了设计这十顶帽子怎么在人和 agent 之间分配。

---

传统管理幅度问你带几个人。混合组织要改问你能安全盯住几条回路。启动一个多 agent 单元前，逐条算。

| 要素 | 算什么 |
|------|--------|
| 回路数 | 同时在跑的自主 agent 回路有几条？ |
| 单条注意力占用 | 每条回路平均要占用人多少注意力？（连续盯防 / 关卡批准 / 只管异常 / 事后抽查） |
| 风险权重 | 这条回路做错的后果多大？（可逆 / 不可逆 / 涉及钱、法律、安全） |
| 升级带宽 | 出了异常，人能不能及时接住？升级路径清不清楚？ |
| 实际幅度 | 不是回路数，是注意力总占用除以人的可用注意力，超过 1 就管崩了 |

这张表把带一群 agent 从一个玄乎的口号，变成一笔能算的账。它会告诉你一个反直觉的结论，想扩大管理幅度，不是加 agent，是降低每条回路的注意力占用，把回路做得更可验证、更可自动化、异常更少，人才能带得更多。

---

明茨伯格的经理，是靠人际关系带来信息、信息支撑决策这台咬合的机器运转的。现在 agent 能承接监测、传播、分配，它把这台机器的好几个齿轮拆下来自己转了。

于是一个更狠的问题冒出来。当一个组织不再靠经理这个信息枢纽运转，而是靠一堆 agent 在岗位之间直接流转信息、直接执行，岗位这个东西，还有没有存在的必要。工作要是能围绕结果直接编成一支队伍，那延续了一百年的岗位、部门、汇报线，就该让位给一种新的组织单元。这是下一章的事。
