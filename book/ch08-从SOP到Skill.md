# 第 8 章　从 SOP 到 Skill

最近一批办公 Agent 与编程 Agent 之间，出现了几种可观察的关联。

Anthropic 的办公 agent 叫 Claude Cowork，官方说它用的是和 Claude Code 同一套 agentic 架构，而 Claude Code 是一个编程 agent。OpenAI 的 ChatGPT Work，内核里嵌着它的编程 agent Codex，官方也确认二者共享同一套执行机制。腾讯把编程的 CodeBuddy 和办公的 WorkBuddy 放进同一个产品矩阵，共享账号和权限。百度那边，编程的 Comate 后来被并进了办公的 DuMate。

这些产品与编程 Agent 共享部分架构或产品能力。编程任务要求系统规划步骤、调用工具、运行测试并检查结果，因此较早形成了连续执行的工作闭环。当这套能力迁移到文档、分析和工单处理等场景，办公 Agent 也能沿用其中一部分。

这些产品的共同点是，标准化的对象从单个动作扩展到可复用、可验证、可移植的能力。这与泰勒对工作方法进行标准化的思路相连。

---

第 1 章讨论了泰勒如何把工作方法写成标准。戴明后来进一步强调，标准还要根据运行结果持续改进。

泰勒关注如何把方法变成组织资产；戴明强调方法需要持续改进，质量也应建在过程之中，而不是只靠末端检验。戴明主张，从一开始就把质量做进产品和流程。

PDCA 循环的早期来源是休哈特。戴明更强调 PDSA，将第三步“检查”改为“研究”：用结果检验预测，再修正理论。第 12 章会继续讨论这一区别。

泰勒和戴明讨论的标准化，主要面向人的工作。Agent 不会像人一样阅读文档后自行理解流程，需要把方法整理成可以调用和执行的形式。

---

第 1 章把泰勒整理工作经验、形成方法卡的过程称为“蒸馏”。Agent 时代的标准化也涉及从实践中提炼方法，再将其整理成可复用的能力。

Agent 的可靠运行仍然需要清晰的方法、工具和验收标准，也需要把质量控制放进执行流程。若 Agent 每周生成大量结果，只在末端安排人工审查，审查者很难覆盖所有输出。质量检查应分布在训练数据、提示词、工具接口、评测和部署等环节。

但标准化的对象变了。2025 年 10 月，Anthropic 提出一个叫 Agent Skills 的东西，同年 12 月把它作为一个开放标准发布。一个技能，是一个文件夹，里面有一份 SKILL.md 写清这个技能是什么、什么时候用，加上指令、脚本、资源。它采用渐进式披露：Agent 先读取元数据，需要时再加载详细指令和资源。这类文件不只是说明文档，也能作为 Agent 调用能力的入口。

Skill 可以被理解为一种机器可读的 SOP。它把工作方法整理为 Agent 能装载的指令、脚本和资源。泰勒把经验写进方法卡；今天，团队可以把方法整理成 Skill，并在不同 Agent 环境中复用。编程 Agent 中的规划、工具调用、执行和验证能力，也逐步迁移到其他工作场景。到 2026 年，Codex、Gemini CLI、GitHub Copilot、VS Code，以及 OpenClaw、Hermes 等运行环境都支持或采用了相近的技能格式。复用并不代表技能会自动变好，仍需根据使用结果维护和修订。

“知识蒸馏”也用于机器学习。Hinton 等人在 2015 年讨论了如何让较小的模型学习较大模型的判断。对应到组织，专家经验不只包括明说的规则，也包括如何比较不完美的选项、处理例外。若只记录结论，而不记录适用条件和判断过程，方法就难以迁移。

---

标准化的对象由动作步骤扩展为可验证的能力模块，这些模块既能供人理解，也能供 Agent 调用。

泰勒标准化的是动作，这一铲怎么挥，产物是给人读的方法卡。agent 时代标准化的是能力模块，一个能力是什么、什么时候用、怎么用、怎么验，产物是人能读、agent 能直接执行的技能包。一个能力模块需要说明何时使用、如何执行和怎样验收。它还应记录适用条件，便于团队在不同 Agent 环境中复用，并根据运行结果修订。这些要求也与第 12 章的验证体系相连。

泰勒把经验写进方法卡；Agent 时代则把工作方法整理进可执行的技能库。组织沉淀的不只是文档，还包括人和 Agent 都能复用的能力模块。

结果单元可以通过复用能力模块减少重复摸索。帕兰提尔将部分现场方法沉淀到平台，供后续团队使用。

---

从实践中提炼方法也有风险，尤其是当组织把记录下来的行为直接当作标准时。

Meta 的内部行为采集计划，展示了这种做法可能引发的争议。2026 年初，扎克伯格和高管在一次闭门会上推演一个叫组织转型的方案，设想把很多团队砍掉最多六成，把十几二十人的专家团队，换成三五个人的小队加一群 AI agent。要让 agent 接手，就得先从员工身上把活蒸馏出来。于是四月，Meta 在美国员工的电脑上线了一个计划，抓取鼠标移动、点击位置、键盘输入，偶尔截屏，覆盖两百多个应用和网站。内部的说法很直白，所有员工都能帮模型变得更好，只要照常做自己的日常工作。有高管对员工说，工作电脑上没有退出这个的选项。

这项计划采集的不是成品文档，而是员工完成工作的动作记录。泰勒用秒表观察工序；Meta 的程序则记录鼠标和键盘操作。两者都试图从行为中提炼工作方法，但后者覆盖的应用范围和数据量更大，也带来隐私与监控问题。

后续进展也显示，这类计划会遇到组织和治理方面的限制。Meta 那轮重组裁了约八千人，但更大的转型卡住了。扎克伯格七月对员工承认，agent 的进展没有按预期加速，这些结构性的赌注还没见效，重组也没有本该有的那么干净。超过一千五百名员工签名反对那个抓取计划，六月下旬，因为一次安全事故，抓到的数据，包括私人对话、绩效信息、敏感度评级，被发现在公司内部能被过度访问，Meta 暂停了这个计划。原本计划的第二波重组，取消了。

从 Meta 的案例和相关研究中，可以看到方法蒸馏的三个限制。

第一，蒸馏会丢失信息，不能视为无损复制。AI 的研究里有一篇著名的论文直接问，知识蒸馏真的管用吗，结论是学生模型表现变好，常常不等于它真的复制了老师的判断，师生的一致率往往只有八九成。换到组织里，员工接触了一份蒸馏出来的方法后表现变好，不等于那个专家的判断真被传了过去，他可能只是被引导着换了个方式搜索、或者独立重造了一个有效解。

第二，有些知识难以通过文档或记录完整传递。哲学家波兰尼有句话，我们能知道的，多于我们能说出来的。一个熟练的人，身上有大量说不清、也写不进文档的东西，它要靠一起干活、靠观察和反复练习才能传递。文档最多是专家能力的一个接口，不是专家本人的复制。

第三，常见行为不一定是值得保留的做法。日志记下的是发生了什么，不是该怎么做。频率最高的那条路，可能是最常见的 workaround、是遗留的约束、是反复犯的那个错。机器从数据里蒸馏出来的，可能是最常见的行为，而不是最该保留的行为。NASA 有个教训库，调查发现只有不到两成的人用过里面的教训，捕获一条教训和真的重新学到它，是两码事。

因此，蒸馏需要持续治理：从真实工作中提炼方法，在实际使用中验证其效果，记录来源和适用条件，并根据新证据修订。没有验证的方法可能只是把旧习惯写了下来；停止更新后，它也可能逐渐失效。

---

写一个给人和 agent 共用的能力模块，不管你叫它 Skill、SOP 还是别的，必须含四样。

| 要素 | 泰勒的方法卡有吗 | 为什么 agent 时代必须有 |
|------|-----------------|----------------------|
| 是什么 / 何时用 | 部分（工序说明） | agent 要先判断该不该用这个能力，元数据比正文先加载 |
| 怎么用（指令 + 工具） | 有（动作步骤） | agent 要能直接调用，不是读了去理解，是装载了去执行 |
| 怎么验（验收 + 证据） | 弱（末端检验） | 戴明式，质量建在过程里，能力模块自带怎么算做对了 |
| 怎么进化（反馈回流） | 无 | 用完的经验要能改进这个模块本身，写一次，越用越强 |

前两个是泰勒的遗产，后两个是戴明的遗产加 agent 的新要求。如果能力模块只描述操作步骤，却没有验收标准和更新机制，它就很难适应新的任务条件。

---

标准化说明了 Agent 如何复用方法，但没有回答另一个问题：当 Agent 可以规划和调用工具时，管理者应授予它多大自主权？

固定技能仍需要权限边界和验收机制。Agent 若能自行规划、调用工具或修改技能，风险范围会进一步扩大。第三部将讨论如何设置和调整它的自治权限。
