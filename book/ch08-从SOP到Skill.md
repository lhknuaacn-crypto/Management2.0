# 第 8 章　从 SOP 到 Skill

有一个规律，藏在最近这批 AI 产品的家谱里，一旦看见就再难忽视。

Anthropic 的办公 agent 叫 Claude Cowork，官方说它用的是和 Claude Code 同一套 agentic 架构，而 Claude Code 是一个编程 agent。OpenAI 的 ChatGPT Work，内核里嵌着它的编程 agent Codex，官方也确认二者共享同一套执行机制。腾讯把编程的 CodeBuddy 和办公的 WorkBuddy 放进同一个产品矩阵，共享账号和权限。百度那边，编程的 Comate 后来被并进了办公的 DuMate。

这一批办公 agent，都和一个编程 agent 血脉相连，有的直接同源，有的同门共栈。为什么。因为编程这件事，最早逼着人把一套完整的做事闭环跑通了：规划、调用工具、执行、验证。写代码天然就要拆任务、调编译器和测试、跑起来、看对不对。当这套闭环在编程场景里被磨得足够可靠，它就成了一个可以移植的内核，从写代码挪到写报告、做分析、处理工单，办公 agent 就长出来了。

这个家谱透出一件事。agent 时代的标准化，标准化的不是动作，是一整套可复用、可验证、可移植的能力。而这，正是泰勒那把秒表，一百年后的样子。

---

第 1 章讲过泰勒，他把怎么干活从工人脑子里搬出来，写成标准。泰勒那套有个毛病，被后来一个人补上了，这个人是 W·爱德华兹·戴明。

泰勒的标准化是静态的，找到最好的方法，定死，让工人照做。戴明说方法不是定死一次就完事的，得持续改进。他还补了一个更根本的洞见，质量不是靠最后检验出来的，是靠系统在过程里建出来的。泰勒解决了把方法变成组织资产，戴明解决了让方法持续进化、让质量长在过程里。戴明有句话，本书后面会反复回来，不要依赖检验来获得质量，而要从一开始就把质量做进产品里。

这里得替戴明说一句公道话。外界常把那个"计划、执行、检查、处理"的 PDCA 循环挂在他名下，其实那套的源头是休哈特，戴明本人强调的是 PDSA，把第三步从检查换成研究，意思是拿结果去检验你的预测、再修正你的理论，而不是机械地走一圈流程。这个区别到第 12 章还要用。

泰勒加戴明，合起来是一套完整的东西，把方法标准化，并让它在过程里持续进化、内建质量。但他们俩标准化的对象，始终是给人的。泰勒的方法卡是给工人读的，戴明的质量体系是给人执行的。标准化的产物，是人照着做的东西。现在，标准化要服务一个不读文档的对象。

---

第 1 章埋过一个词，叫蒸馏。泰勒把工人脑子里说不清的经验，提炼、浓缩成一份别人能照着用的方法卡，这是最早的、手动的蒸馏。这一章，这个词要正式登场，因为 agent 时代的标准化，本质就是一次更彻底的蒸馏。

泰勒的标准化和戴明的内建质量、持续改进，在 agent 时代是刚需，而且刚需到极致。一个 agent 要可靠，需要的正是泰勒式的标准，清楚的方法、工具、验收，加戴明式的过程质量，把质量建进流程，而不是等产出之后再靠人工挑错。戴明那句别靠末端检验，在 agent 时代简直是预言。你不可能在一个 agent 每周产出一千个东西的流水线末端，靠一个人肉审查者兜住质量，质量必须建在上游，建在训练数据里、提示词里、工具接口里、评测里、部署流程里。

但标准化的对象变了。2025 年 10 月，Anthropic 提出一个叫 Agent Skills 的东西，同年 12 月把它作为一个开放标准发布。一个技能，是一个文件夹，里面有一份 SKILL.md 写清这个技能是什么、什么时候用，加上指令、脚本、资源。它的妙处在渐进式披露，agent 先读元数据知道有这么个技能，用到时才加载详细指令，需要时才调底层资源。这不是给人读的文档，是给 agent 调用的能力包。

Skill 就是一份 SOP，一份标准作业流程，只不过它从给人读的纸，变成了机器能读、能直接跑、还能自我迭代的东西。这正是蒸馏在今天的形态。泰勒把工人的经验手动蒸馏成方法卡，今天我们把一套做事的方法蒸馏成 Skill。编程 agent 里磨出来的那个规划、调用、执行、验证的内核，被打包成可移植的技能，从 Claude Code 长出 Cowork，从 Codex 长出 ChatGPT Work。到 2026 年，一批独立客户端都实现了这套格式，OpenAI 的 Codex、Gemini CLI、GitHub Copilot、VS Code，以及 OpenClaw、Hermes 这类开源 runtime。写一次，许多 agent 能继承、能跨平台复用、还能在用的过程里被改进。泰勒的方法卡是死的，要人去教；蒸馏成的技能是活的，能自己装载和进化。

这件事还有一个更机器的源头。AI 自己也有个词叫知识蒸馏，2015 年 Hinton 几个人提出来的，用一个大模型当老师，训练一个小模型学它的判断。他们说了一句对组织也成立的话，知识不只在模型当前的参数里，更在这些参数共同实现的输入输出关系里，在它对错误答案的相对判断里。换句话说，一个专家真正值钱的，不只是他说得出的规则，更是他对多个不完美选项的排序、他的犹豫、他对例外的处理。蒸馏一个专家，如果只记下他的结论，等于什么都没蒸馏到。

---

把这条线捋到底，泰勒的标准化就升级了。标准化的对象，从人照着做的动作，变成了人机共用的、可验证的能力模块。

泰勒标准化的是动作，这一铲怎么挥，产物是给人读的方法卡。agent 时代标准化的是能力模块，一个能力是什么、什么时候用、怎么用、怎么验，产物是人能读、agent 能直接执行的技能包。这个升级有三层意思。一是产物同时服务人和机器，一份好技能，人读了懂业务，agent 读了能执行，一份东西两用。二是它内建了戴明式的验证，一个合格的能力模块不只说怎么做，还说怎么验做得对不对，这正好接第 12 章。三是它是可复用、可移植、可进化的资产，写一次，跨 agent 继承，还能在使用中改进。

一句话，泰勒把方法从工人脑子搬进了方法卡，agent 时代把方法从方法卡搬进了可执行的技能库。组织沉淀下来的不再是文档，是能力，一种人和 agent 都能调用、还越用越强的活资产。

这也回答了上一章末尾的问题，结果单元靠什么高效运转，靠这些蒸馏出来的能力模块。帕兰提尔的小队能一次比一次从更高的起点开始，正因为它把现场磨出的方法，蒸馏成了平台上可复用的能力，它蒸馏的不是这次怎么干，是这类事的能力怎么被下一个 agent 继承。

---

但蒸馏这件事，有它的阴影，这本书不打算绕过去。

有一家公司，把蒸馏推到了最生猛、也最有争议的地步，是 Meta。2026 年初，扎克伯格和高管在一次闭门会上推演一个叫组织转型的方案，设想把很多团队砍掉最多六成，把十几二十人的专家团队，换成三五个人的小队加一群 AI agent。要让 agent 接手，就得先从员工身上把活蒸馏出来。于是四月，Meta 在美国员工的电脑上线了一个计划，抓取鼠标移动、点击位置、键盘输入，偶尔截屏，覆盖两百多个应用和网站。内部的说法很直白，所有员工都能帮模型变得更好，只要照常做自己的日常工作。有高管对员工说，工作电脑上没有退出这个的选项。

看清楚它蒸馏的是什么。不是成品文档，是员工完成一件事的动作序列。泰勒当年拿着秒表站在工人旁边，记下他怎么搬铁；Meta 用一个程序，记下知识工作者怎么点鼠标、怎么在应用之间穿行。一个是手动的秒表，一个是无声的、全时的、长在你电脑里的秒表。这是泰勒那套东西，一百年后最彻底、也最让人不安的版本。

后来的事，正好是这本书免疫立场的注脚。Meta 那轮重组裁了约八千人，但更大的转型卡住了。扎克伯格七月对员工承认，agent 的进展没有按预期加速，这些结构性的赌注还没见效，重组也没有本该有的那么干净。超过一千五百名员工签名反对那个抓取计划，六月下旬，因为一次安全事故，抓到的数据，包括私人对话、绩效信息、敏感度评级，被发现在公司内部能被过度访问，Meta 暂停了这个计划。原本计划的第二波重组，取消了。

Meta 这件事坐实了蒸馏的三条边界，恰好是学界早就提出的三个最强反驳。

一是蒸馏是有损的，不是无损复制。AI 的研究里有一篇著名的论文直接问，知识蒸馏真的管用吗，结论是学生模型表现变好，常常不等于它真的复制了老师的判断，师生的一致率往往只有八九成。换到组织里，员工接触了一份蒸馏出来的方法后表现变好，不等于那个专家的判断真被传了过去，他可能只是被引导着换了个方式搜索、或者独立重造了一个有效解。

二是有些知识，原则上就蒸馏不出来。哲学家波兰尼有句话，我们能知道的，多于我们能说出来的。一个熟练的人，身上有大量说不清、也写不进文档的东西，它要靠一起干活、靠观察和反复练习才能传递。文档最多是专家能力的一个接口，不是专家本人的复制。

三是最危险的一条，蒸馏很容易把昨天的常见行为，当成今天该守的最佳实践。日志记下的是发生了什么，不是该怎么做。频率最高的那条路，可能是最常见的 workaround、是遗留的约束、是反复犯的那个错。机器从数据里蒸馏出来的，可能是最常见的行为，而不是最该保留的行为。NASA 有个教训库，调查发现只有不到两成的人用过里面的教训，捕获一条教训和真的重新学到它，是两码事。

所以蒸馏不是把一个人的本事原样倒进一个罐子。它是一个要治理的过程，从真实的表现里提炼出一个更省、可复用、可检视的东西，在用的人那里验它准不准、有没有用，记下它从哪来、在什么条件下成立、什么时候别用，再根据后来的结果不断修订。只有方法，得到的是口诀；没有更新的回路，得到的是遗迹。

---

写一个给人和 agent 共用的能力模块，不管你叫它 Skill、SOP 还是别的，必须含四样。

| 要素 | 泰勒的方法卡有吗 | 为什么 agent 时代必须有 |
|------|-----------------|----------------------|
| 是什么 / 何时用 | 部分（工序说明） | agent 要先判断该不该用这个能力，元数据比正文先加载 |
| 怎么用（指令 + 工具） | 有（动作步骤） | agent 要能直接调用，不是读了去理解，是装载了去执行 |
| 怎么验（验收 + 证据） | 弱（末端检验） | 戴明式，质量建在过程里，能力模块自带怎么算做对了 |
| 怎么进化（反馈回流） | 无 | 用完的经验要能改进这个模块本身，写一次，越用越强 |

前两个是泰勒的遗产，后两个是戴明的遗产加 agent 的新要求。一个只有怎么用、没有怎么验和怎么进化的能力模块，是死的 SOP，不是活的技能。

---

标准化解决了 agent 怎么可靠地执行。但它绕开了一个更烫手的问题，这个会自己找路、能装载技能、还能自我改进的执行体，你到底该给它多大的自主权。

一个只按固定技能执行的 agent，你可以放心。可一旦它开始自己规划、自己调用工具、甚至自己改写它用的技能，你还敢完全放手吗。给太少，它成了昂贵的自动补全；给太多，它可能删了你的数据库还撒谎。这是第三部要正面回答的问题，而它的第一原则，恰恰颠覆我们对自治的直觉，自治从来不是一个给或不给的开关。
