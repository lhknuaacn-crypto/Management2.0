# 第 9 章　自治不是二元开关

问一个看似简单的问题，你敢让一个 agent 自己发邮件吗。

大多数人的第一反应是二选一，要么敢，让它自动发，要么不敢，每封都得我点确认。但真正跑过 agent 的人，答案是第三种。

Meta 的个人 agent Muse 能替你订行程、买东西、发邮件，可它不是全自动的，背后有一个独立的东西叫 Sentinel，专门审查任何要触网的动作，该拦的拦、该问的问。xAI 的 Grok Bot，默认姿态是先起草、别发送，遇到发邮件、发布、购买、删除、改权限这些有后果的动作，它停下来等你点头。小团队里那些真把 agent 用出效果的操作者，铁律更狠，自主权是挣来的，agent 先只做起草，你按发送，等你攒够几十个真实样本、确认它在这件事上靠谱了，才放开让它自己发。

看清楚这几个的共同点。没有一个是全自动或全手动的开关，它们都是一道阶梯，从只能建议，到可以起草，到低风险的自己做、高风险的要批准，一格一格往上爬。而爬到哪一格，不看这个 agent 看起来多聪明，看它在这件具体的事上被验证过多少次、做错了能不能兜住。

这就是管理 agent 的第一原则。它颠覆我们对自治的直觉，自治不是一个状态，是一道能精细调节、还能随时往回收的滑杆。

---

第 3 章借麦格雷戈讲过 X 理论和 Y 理论，你对人的假设会变成现实。X/Y 理论还有一层第 3 章没展开，它其实是在谈你给人多少自主权。

X 理论的管理者假设人不可信，于是收紧自主，严密监控、细碎审批、层层把关。Y 理论的管理者假设人可信，于是放开自主，给空间、给授权、给自我引导的余地。麦格雷戈这层洞见揭示了一件事，给多少自主权，是管理最核心的决策之一。给多了失控，给少了浪费，而给多给少，取决于你对被管理者能力的判断。

麦格雷戈想让管理者从 X 走向 Y，他相信多给人一点信任和自主，人会成长起来、会回报你。这个方向对人是对的。可他谈的授权，有两个隐含前提。一，被授权的是人，人有天生的判断和这事不对我不干的刹车。二，授权大体是一次性的、粗粒度的，你信任一个人，就把一个岗位的责任交给他，不会精确到这个动作可以、那个动作要问。对 agent，这两个前提都不成立。

---

麦格雷戈那个核心决策，给多少自主权，在 agent 时代是天天要做、而且要做得极其精细的决策。管一个 agent，本质上还是在回答麦格雷戈的问题，这个执行体我给它多大的自主。给太少，把它当不可信的自动补全，你收获琐碎；给太多，把它当无所不能，你收获灾难。

但 agent 的自治，不能像对人那样一次性、粗粒度地给。因为 agent 的能力是不均匀的。它可能在起草邮件上极其可靠，在判断这封邮件该不该发上很不可靠。你没法像信任一个人那样整体信任它，只能针对具体的动作、具体的风险分别授权。Agent Harness 恰好提供了这种精细控制的手段，能精确到能读什么、能写什么、能调什么、能花多少、什么必须问人。

于是有了各种分级授权的机制，Muse 的 Sentinel、Grok Bot 的先起草后放行、Palantir 那种在你的权限下运行、改动生产必须显式批准、改之前先在隔离分支测。这些工具把自治从一个开关，做成了一个可以逐格调节的滑杆。本书把这个滑杆刻成一道六级阶梯，这是本书提出的分级，参考了学界的自治层级框架，但不完全等同于其中任何一个：只生成，到在文档里辅助，到执行有界任务，到跨应用工作流，到操作受治理流程，到持久组织 actor，也就是所谓真·数字员工。绝大多数产品老老实实待在三到五级之间，而第六级，那个营销话术里天天喊的真正的数字员工，至今没有被大规模、可信地证明过。

---

把这条线捋到底，新原则就是，自治是一道渐进的阶梯。按已被验证的能力、按后果的可逆性，一格一格放开；一旦失误，一格一格收回。

这里有三个关键词，缺一不可。

渐进。从只能起草开始，做对了、验证够了，才升到低风险自己做，再往上。小团队操作者那句先起草、后放行、自主权是挣来的，就是这个。

按证据，不按印象。这是它和信任人最大的不同。你信任一个人，可以凭感觉、凭他给你的印象。你给 agent 放权，只能凭证据，它在这件事上跑过多少次、成功率多少、做错了能不能兜住。有一个实用的做法是先攒一个几十例真实案例的评测集，Isenberg 提过五十例这个量级，每次改提示、换工具、升级模型都重跑一遍。但要说清楚，这是该不该放权的一个起点，不是过了就自动放权的安全阈值。

可降级。这是 agent 独有的、人做不到的。一个 agent 一旦在某一格出了错，你可以立刻把它降回上一格，它不会因此士气受挫、感觉不被信任。这是管 agent 比管人多出来的一个奢侈，授权是可逆的。

而阶梯的顶端，第六级那个真·数字员工，不是一个模型能力问题，是一个机构成就。一个 agent 要真正配得上数字员工这个称呼，得同时满足一长串条件，可撤销的独立身份、明确的角色边界、政策绑定的权限、能力的持续证据、记忆的治理、学习的管控、可审计、可问责的人类主体、可退出可交接。持久地运行，不等于就是员工。谁跟你说他们家的 agent 已经是真正的数字员工了，你拿这张清单去对，一条条问。

用大师卡那句话说，管人靠相信他们的潜能，管 agent 靠他们潜能的证据。这个按证据放权、按风险收权的阶梯，就是证据落地的样子。

---

给任何一个 agent 授权前，先用两样东西给它定位。

第一，用七个问题划清它的边界，这是小团队操作者 Isenberg 的清单。什么唤醒它。它需要什么上下文。它能调用什么工具。它能自主做什么。发送或执行前，什么必须批准。什么情况升级给人。你怎么知道它成功了。

第二，把它放到六级阶梯上。

| 级 | 它能做到 | 人守在哪 |
|----|---------|---------|
| 1 生成 | 产出文本、答案 | 全程把关 |
| 2 辅助 | 改你正打开的东西 | 连续审 |
| 3 有界任务 | 用工具产出一个交付物 | 关卡批准 |
| 4 跨应用工作流 | 跨应用跑多步 | 关键关口批准 |
| 5 受治理流程 | 在系统里按政策行动 | 政策审查加异常接管 |
| 6 持久组织 actor | 持角色、记忆、授权 | 尚未被大规模证明，别轻易声称到了这一级 |

填完这两样，你就知道这个 agent 现在在第几级、边界在哪、什么时候该升、什么时候必须降。没做这个定位就给一个 agent 放权，等于不看驾照就把车钥匙扔给一个你不知道会不会开车的人。

---

渐进式自治解决了给单个 agent 多少权。但当一个组织里有几十上百个 agent，每个都在自己的授权级别上跑，一个更大的问题冒出来，这一整套谁能读什么、谁能写什么、谁必须问谁的规则，本身该怎么组织。

如果每个 agent 的权限都是临时拍的、散落各处的，这个组织会乱成一锅粥。你需要一套稳定的、成文的、可执行的规则体系，一个 agent 该有的身份、角色、管辖范围、审批链，都清清楚楚地定下来。这听上去像不像一百年前韦伯研究的那个东西，科层制。下一章，看这个被骂了一百年的官僚制度，怎么在 agent 时代变成不得不重建的东西。
