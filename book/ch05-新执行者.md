# 第 5 章　新执行者

AI 产品的命名变化，也记录了它们承担的工作范围。

2023 年，大家管 AI 叫 assistant，助手，你问它答。很快变成 copilot，副驾，微软的词，意思是你还在开飞机，它在副驾位上帮你。再往后是 cowork，Anthropic 的词，Claude 和你一起干活，它开始离开对话框，去碰你的文件。然后是 work，OpenAI 直接把产品叫 ChatGPT Work，去掉所有修饰，就"干活"两个字。到了中国，叫办公，阿里的千问办公、字节的豆包办公，一个能处理协调、研究、报告、沟通的宽泛职能。最亲切的一个叫搭子，陪你吃饭、健身、干活的伙伴，能干活，又亲切得不让你有压力。

这些名称大致显示了产品工作范围的变化：从回答问题，到协助操作，再到完成一段任务。名称本身不能证明产品有多少自主权，管理者还需要看它实际能调用什么工具、能执行哪些动作。

这些产品的运行方式和管理要求并不相同。

Meta 的 Muse，是你一个人的贴身管家，管你的邮件、日程、购物、行程、健康、智能家居，藏在一个亲切的关系背后。xAI 的 Grok Bot，是一支看得见的队伍，一堆有名有姓、分了角色的 Bot，互相协调、交接。微软的 Copilot，老老实实待在 Word 和 Excel 里，帮你改你正打开的那个文档。SAP 的 Joule，在企业系统里跑一整套受治理的业务流程。

它们都被称为 AI Agent，但个人助理、应用副驾、业务流程执行者和 Agent 队伍拥有不同的权限与风险。管理者需要先辨认它的形态。

---

要理解这些执行者，可以从赫伯特·西蒙的有限理性谈起。西蒙研究决策者如何在信息、计算能力和时间都有限的条件下作出选择。他曾获图灵奖和诺贝尔经济学奖。

古典经济学常用完全理性的决策者作为分析前提：他知道所有选项，也能比较全部后果。西蒙指出，现实中的人受信息、计算能力和时间限制，通常只能找到一个达到要求的方案。

西蒙用“搜索”和“满意即止”描述这一过程。决策者先寻找选项，再选择达到期望水平的方案，不会无限搜索一个理论上的最优解。

西蒙还指出，组织会影响决策者能够接触的信息、看见的选项，以及被默认接受的前提。管理制度因此也在塑造决策者的认知边界。

西蒙讨论的决策者是人。Agent 的边界则更多由上下文窗口、检索范围、算力预算和训练数据等条件决定。

---

有限理性也可以用来分析 Agent，但限制因素有所不同。

Agent 的认知边界包括上下文窗口、检索范围、延迟和算力预算，以及训练数据的时间范围。管理者可以据此设置任务目标、停止条件和置信要求，避免系统无休止地搜索并消耗预算。

Agent 的认知边界会随工具、权限和运行环境改变，也因此形成不同形态。

上一章讨论了 Harness 如何让模型持续执行任务。同一个模型接入不同的工具、运行环境和权限后，能力和风险会不同：在 Word 中它可能是文档副驾，在云电脑中可能协调一组 Bot，在手机上则可能处理日程或购物。产品形态由模型和这些配置共同决定。

Muse、Grok Bot、Copilot、Joule、千问办公和 Kimi 等产品，可能使用相近的底层模型，但形态并不相同。本书将它们归纳为七种数字员工：内嵌增强器、有界工作合同工、个人代表、流程专才、角色型数字同事、数字员工队伍、受治理 agent 层。每一种对应一种不同的数字员工，也要求不同的管理方式。

因此，Agent 不是单一形态。辨认不同类型的数字员工，是后续讨论管理方式的起点。

---

管理者可以先给 Agent 做形态定位。

定位时要看五个方面：

| 坐标 | 问什么 |
|------|--------|
| 自治 | 它能自己往前推多远？（六级阶梯，从只生成到持久组织 actor） |
| 存活面 | 它活在哪？（应用内 / 桌面 / 个人云 / 消息网关 / 企业系统） |
| 范围 | 它拥有多大的工作单元？（一句话 / 一个文件 / 一个任务 / 一整个流程 / 一个角色 / 一支队伍） |
| 人在环 | 人在哪儿介入？（连续共同生产 / 关卡批准 / 只管异常 / 政策审查 / 事后审计） |
| 归属 | 谁是主人？（消费者个人的 / 企业部署的） |

这五个方面能帮助管理者判断该采用哪种治理方式。多 Agent 队伍需要组织设计；个人 Agent 则更依赖清晰的委托和权限管理。下一章讨论管理者如何监督这些不同的执行回路。

管理者需要先辨认执行者的形态，再为它设置相应的认知和权限边界。

Agent 能快速生成大量选项，决策的难点因而转向核实前提和评估后果。给它划定搜索范围、预算和停止条件时，也要了解它没有检索哪些材料。

---

启动人机工作单元前，可以用这五项记录 Agent 的形态与治理要求。

| 坐标 | 这个 agent 是…… | 落点 |
|------|----------------|------|
| 自治 | 六级里的第几级？ | 大多数产品在三到五级；第六级（真·数字员工）还没被大规模证明 |
| 存活面 | 应用内 / 桌面 / 个人云 / 网关 / 企业系统 | 决定它能碰到什么，也决定它的风险面 |
| 范围 | 一句话 / 文件 / 任务 / 流程 / 角色 / 队伍 | 范围越大，验证和治理越重 |
| 人在环 | 连续 / 关卡 / 异常 / 审计 | 决定人的注意力花在哪 |
| 归属 | 消费者个人 / 企业部署 | 决定谁授权、谁担责、记忆归谁 |

填写这张表后，可以明确它属于哪种形态、采用何种治理方式，以及人应在哪些环节介入。

---

形态越复杂、自治范围越大，管理者需要承担的组织设计和监督工作通常越多。

只修改当前文档的副驾，风险范围有限；能够自行协调和交接任务的 Agent 队伍，则需要角色设计、权限边界和冲突处理机制。

下一章讨论管理幅度：Agent 数量增加后，管理者究竟能监督多少条执行回路？这个问题不能只用传统的下属人数来回答。
