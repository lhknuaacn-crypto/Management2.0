# 第 5 章　新执行者

给一个词的演变排个队，你会看到一部压缩的历史。

2023 年，大家管 AI 叫 assistant，助手，你问它答。很快变成 copilot，副驾，微软的词，意思是你还在开飞机，它在副驾位上帮你。再往后是 cowork，Anthropic 的词，Claude 和你一起干活，它开始离开对话框，去碰你的文件。然后是 work，OpenAI 直接把产品叫 ChatGPT Work，去掉所有修饰，就"干活"两个字。到了中国，叫办公，阿里的千问办公、字节的豆包办公，一个能处理协调、研究、报告、沟通的宽泛职能。最亲切的一个叫搭子，陪你吃饭、健身、干活的伙伴，能干活，又亲切得不让你有压力。

assistant、copilot、cowork、work、办公、搭子。这不是随口起的名字，是一部委托权一步步加深的历史。从帮我答一句，到替我把活干完，每换一个词，交给机器的自主权就多一分。厂商在用产品名小心试探一件事：这东西到底能替你干多少，你又能接受它替你干多少。

而当你真要管这些东西，第一个撞上的问题是，它们根本不是一种东西。

Meta 的 Muse，是你一个人的贴身管家，管你的邮件、日程、购物、行程、健康、智能家居，藏在一个亲切的关系背后。xAI 的 Grok Bot，是一支看得见的队伍，一堆有名有姓、分了角色的 Bot，互相协调、交接。微软的 Copilot，老老实实待在 Word 和 Excel 里，帮你改你正打开的那个文档。SAP 的 Joule，在企业系统里跑一整套受治理的业务流程。

它们都被叫做 AI agent。可你管 Muse 的方式，和你管 Grok Bot 的方式，是两门完全不同的手艺。在管一个 agent 之前，你得先知道，你管的到底是哪种 agent。

---

要回答这是个什么东西，先请出一个专门研究东西怎么做决定的人，赫伯特·西蒙。他拿过图灵奖，也拿过诺贝尔经济学奖，一辈子追一个问题：一个决策者，在信息不全、算力有限、时间不够的时候，到底怎么做选择。

古典经济学有个天真的假设，决策者是理性的，他知道所有选项、算得清所有后果、总能选出最优解。西蒙一巴掌拍碎了它。他说真实世界里没有这种神，人的理性是有限的，你不可能知道所有选项，不可能算清所有后果，脑子和时间都不够用。

西蒙解决的是一个至今没人绕得开的难题。人做决策，是在有限的认知里找一个够用的，而不是在无限的选项里挑一个最优的。他造了两个词，管理学和 AI 到今天还在用。一个是搜索，选项不是天上掉下来的，你得去找。一个是满意即止，你不会一直找下去，找到一个够好、达到期望水平的，就停下来选它。用他自己的话，一旦他发现一个达到期望水平的选项，就会终止搜索，选择它。

西蒙还看清一件事，组织的作用，就是塑造决策者能看到什么——什么信息到他面前、什么选项在他视野里、什么前提被当成理所当然。管理，某种意义上就是在管决策者的认知边界。

但西蒙脑子里的决策者，始终是人。人的认知边界相对固定，一个人的脑子就那么大，一天就那么长。现在混进来一种认知边界完全不一样的东西。

---

西蒙那套有限理性，在 agent 身上非但没失效，反而是理解 agent 最好的框架。

一个 agent 也是在有限理性里做决定，只不过它的边界换了位置：上下文窗口有多大、能检索到的资料覆盖多广、延迟和算力预算多少、训练数据截止到哪天。这些就是 agent 版的认知边界。所以管 agent 也得给它设期望水平、设停止规则、设置信阈值，跟西蒙说的一样。满意即止这件事，agent 也得会，不然它会一直搜下去，烧光你的预算。

但西蒙没料到一件事。决策者从人换成 agent，它的认知边界不再固定，而且开始分化成不同的形状。

上一章说过，Agent Harness 这层架构成熟了，让模型从会应答变成能持续干活的执行体。真正要紧的是，同一个底层模型，装进不同的 Harness、接不同的存活面、给不同的权限，会长成完全不同的东西。装进 Word 里，它是个副驾；装进一台云电脑加一队 Bot，它是支员工队伍；装进你的手机加你的日历、购物、健康，它是个贴身管家。技术不再生产一种 AI，而是生产一个物种谱系。

于是市场上同时冒出 Muse、Grok Bot、Copilot、Joule、千问办公、Kimi，底层可能用着相似的模型，形态却天差地别。这些形态，本书把它归拢成七种数字员工：内嵌增强器、有界工作合同工、个人代表、流程专才、角色型数字同事、数字员工队伍、受治理 agent 层。每一种对应一种不同的数字员工，也对应一门不同的管理手艺。

这就是本书的第二条主轴。Agent 不是一个东西，是一个正在分化的物种谱系。管理学第一次要面对数字员工的形态学。

---

把这条线捋到底，第一个原则冒出来了：在管一个 agent 之前，先给它做形态定位。

怎么定位，不是问它多智能，是问五个坐标。

| 坐标 | 问什么 |
|------|--------|
| 自治 | 它能自己往前推多远？（六级阶梯，从只生成到持久组织 actor） |
| 存活面 | 它活在哪？（应用内 / 桌面 / 个人云 / 消息网关 / 企业系统） |
| 范围 | 它拥有多大的工作单元？（一句话 / 一个文件 / 一个任务 / 一整个流程 / 一个角色 / 一支队伍） |
| 人在环 | 人在哪儿介入？（连续共同生产 / 关卡批准 / 只管异常 / 政策审查 / 事后审计） |
| 归属 | 谁是主人？（消费者个人的 / 企业部署的） |

这五个坐标一填，你手里的 agent 是哪种数字员工就清楚了。而它是哪种，直接决定你用哪门手艺。team 形态的 agent，管它靠组织设计；单个 personal agent，管它靠委托治理。同一个管 agent 的命题，会因为形态不同，裂成完全不同的两门学问，这是下一章要展开的。

用西蒙的话说，管理者的活儿从给决策者划定认知边界，变成了先辨认这是哪种决策者，再给它划边界。

这里还藏着西蒙留给 agent 时代最锋利的一句提醒。西蒙那个年代，稀缺的是产生选项的能力，人想不出那么多方案。agent 把这件事翻了过来。机器能生成的选项多到过剩，过剩本身成了新的认知边界。稀缺的不再是想出选项，而是验证前提和后果。所以管 agent 的新纪律是，刻意地给它划界，给它一个明确的认知半径、一个搜索成本、一个停止规则，还要它交代哪些选项它根本没查过。

---

任何一个人机单元启动前，先用五个坐标给它拍张 X 光。

| 坐标 | 这个 agent 是…… | 落点 |
|------|----------------|------|
| 自治 | 六级里的第几级？ | 大多数产品在三到五级；第六级（真·数字员工）还没被大规模证明 |
| 存活面 | 应用内 / 桌面 / 个人云 / 网关 / 企业系统 | 决定它能碰到什么，也决定它的风险面 |
| 范围 | 一句话 / 文件 / 任务 / 流程 / 角色 / 队伍 | 范围越大，验证和治理越重 |
| 人在环 | 连续 / 关卡 / 异常 / 审计 | 决定人的注意力花在哪 |
| 归属 | 消费者个人 / 企业部署 | 决定谁授权、谁担责、记忆归谁 |

填完这张卡，你就知道三件事：这是哪种数字员工、该用哪门手艺、人必须守在哪一环。一个连形态都没定位就上线的 agent，等于你雇了个人，却不知道他是保安、会计还是 CEO。

---

给 agent 做完形态定位，你会撞见一个扎心的事实。这七种形态里，越往上，越接近真·数字员工，人要操的心越多，不是越少。

一个只在 Word 里改文档的副驾，你几乎不用管它。一支能自己协调、自己交接、自己往下跑的数字员工队伍，你反而要为它设计组织、划分权限、盯着它们别互相踩踏。

这就带出下一章那个最反直觉的问题。agent 越强、越像一支队伍，管理者能带的数目，到底是变大了还是变小了。一个经理传统上能带五到七个人，现在他能带多少个 agent，带 agent 和带人，又是不是同一件事。
