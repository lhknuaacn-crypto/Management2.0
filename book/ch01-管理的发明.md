# 第 1 章　管理的发明

十九世纪末，美国的钢铁厂里有一个问题，没人答得上来：同样是搬生铁，怎么搬才算对。

每个工人凭自己的习惯搬，有快有慢。方法藏在各人脑子里，师傅带徒弟，谁也说不清哪一种最好。工人还会故意慢下来，因为干快了，老板只加任务、不加钱。一个叫弗雷德里克·泰勒的工头，决定把这件事弄清楚。

在泰勒眼里，这是一整套的浪费，而且工人和老板互相提防，各藏一手。

他把"怎么干活"从工人的经验里提取出来，交给管理者研究。他用秒表测量动作，把搬生铁拆成步骤，比较不同做法，再写成标准训练工人。

这件事后来有了个名字，叫科学管理。管理开始被当作一门可以研究的学问，不再只依赖老板个人的经验。

泰勒做的事，也可以称为蒸馏：把分散在工人身上的经验，提炼成别人能复用的方法。这个概念会在后文继续出现。

一百多年后，标准化的对象扩大了。需要提炼的不只是搬铁的动作，还有一整套做事方法；执行者也多了能自行调用工具的软件。

---

今天我们很容易嘲笑泰勒。拿着秒表掐时间，把人当机器，"泰勒制"几乎成了血汗工厂的代名词。

这种评价忽略了泰勒要解决的问题：工业化扩大协作规模后，怎样让多人按可复用的方法完成工作。

他的答案有四条，写在 1911 年那本《科学管理原理》里。为每一个工作环节发展出一门科学，取代凭经验的大概齐。科学地挑选和训练工人，而不是让他们自生自灭。管理者和工人真诚合作，确保工作照科学的方法走。管理者和工人几乎均分工作和责任，管理者管方法和计划，工人管执行。

泰勒自己有一句话：管理的首要目标，是让雇主获得最大的繁荣，同时让每一个雇员也获得最大的繁荣。他的本意不是压榨。他真诚地相信，把方法科学化、把蛋糕做大，老板和工人能一起得利，而不是零和地互相提防。

第四条把方法设计交给管理者，成为组织职责的一部分。过去，做法依赖工人的经验；工人离开，经验也可能随之流失。把方法写下来并交给其他人使用，才让组织能够积累经验。秒表只是手段，管理者开始系统地设计工作，才是这项实践留下的影响。

泰勒的方法适用于稳定、可重复、可测量的工作。工作需要临场判断，或条件经常变化时，测量动作并不能替管理者找到合适的方法。泰勒也倾向于假设，管理者可以提前确定最好的做法；面对持续变化的工作，这个假设就不够用了。

计算机最初执行预先写好的指令。大模型出现后，软件能够根据上下文生成答案，但通常仍是问一句、答一句。最近几年，模型开始接入工具、记忆和持续运行的环境，可以接收目标、拆解任务、调用工具并根据中间结果调整步骤。这类软件通常称为 Agent。本书使用这个词时，指能够围绕目标连续执行任务的软件。
---

把方法从个人经验中提取出来，变成组织可以复用的资产，这项工作今天仍然重要，也是 Agent 能稳定执行任务的前提。

讨论 Agent 时，可以先沿用管理者熟悉的问题：它承担什么工作、拥有多大权限、怎样验收结果。回答这些问题时，再区分软件与人的不同。

Agent 要可靠地完成工作，同样需要清楚的任务、适用条件、工具和验收标准。今天对应的配置包括提示词、工具接口、检索来源、权限、测试和升级规则。名称变了，管理者仍要把工作设计清楚。

一套不合适的方法交给工人，工人有时会停下来调整；交给 Agent，它可能按同样的方式重复执行。管理者因此需要在上线前检查方法、权限和验收条件，并监测执行结果。

Agent 并没有让标准化退场。它把标准化推到了新的层次。

泰勒标准化的是动作——这一铲该怎么挥、手往哪放、停几秒。他把动作写进方法卡，交给工人照着做。今天我们把一套做事的方法写成 agent 能直接执行的技能，叫它 Skill。Skill 本质上就是一份 SOP，一份标准作业流程，只不过它不再是给人读的纸，而是机器能读、能直接跑的东西。标准化这件事没变，变的是它的载体：从人照着做的动作，变成机器照着跑的流程。

测试也一样。泰勒拿着秒表一遍遍测哪套动作最省力，这就是测试。今天 agent 的评测，是更快、更密的测试——同一个目标，agent 跑出几条不同的路径，哪条更好，当场跑一遍评测就见分晓；改一次提示词、换一个工具，就能把整套评测重跑一遍。泰勒一天测几回，今天一分钟测几十回。测试不但没少，反而成了家常便饭。

变化的是标准化的位置。Agent 接入 Harness 后，可以规划步骤、调用其他 Agent，并根据结果调整路径。把每一步都预先写死，会限制这种执行方式。管理者需要明确目标、禁止事项和验收方法；具体路径可以留给 Agent 探索，再通过更频繁的测试检查结果。

Palantir 的 AI FDE 就是这么用的。你用自然语言给它一个目标，它自己决定怎么建数据管道、怎么改结构、怎么配权限。它不照你写死的步骤走，它自己找路，而你守住的是目标、权限和验收。

科学管理的关注点从动作设计延伸到任务委派。泰勒规定工序中的动作；今天的管理者还要说明预期结果、权限边界和验收方式，并决定哪些执行步骤可以交给 Agent。

泰勒要求管理者设计工作。Agent 进入组织后，管理者还要定义执行体的边界：它能读写什么、可以调用哪些工具、预算多少，以及何时必须停下来询问。设计工作之外，还要设计权限和监督方式。

Agent 已经分化成不同形态。第二部会逐一讨论这些形态及其管理要求。

---

落到一张能用的表上。泰勒给每个工序配一张方法卡，写清怎么干。agent 时代，给每个 agent 配一张能力边界卡，写清边界。

| 泰勒的方法卡（管动作） | Agent 的能力边界卡（管边界） |
|----------------------|----------------------------|
| 这一步怎么做 | 要什么结果（不规定怎么做） |
| 用什么工具 | 能调哪些工具、不能碰哪些 |
| 标准工时 | 能花多少（token / 时间 / 钱）的预算上限 |
| 怎么检验合格 | 用什么验收测试、证据是什么 |
| —— | 什么情况必须停下来问人（升级规则） |
| —— | 哪些是绝对禁止的捷径（反目标） |

这张卡改变了管理者需要写明的内容。方法卡告诉工人怎样完成动作；边界卡则说明 Agent 要交付什么、可以使用哪些工具、怎样验收，以及何时必须交回给人。边界或验收条件缺失时，组织很难判断 Agent 是否仍在授权范围内。

---

泰勒讨论了工序如何标准化，但公司为何存在、这些工序为何要由同一组织协调，仍是另一个问题。下一章转向这个问题。Agent 正在降低寻找、协商和监督的成本，公司边界和岗位结构也因此面临新的选择。
