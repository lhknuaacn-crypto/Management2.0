# 第 1 章　管理的发明

十九世纪末，美国的钢铁厂里有一个问题，没人答得上来：同样是搬生铁，怎么搬才算对。

每个工人凭自己的习惯搬，有快有慢。方法藏在各人脑子里，师傅带徒弟，谁也说不清哪一种最好。工人还会故意慢下来，因为干快了，老板只加任务、不加钱。一个叫弗雷德里克·泰勒的工头，决定把这件事弄清楚。

在泰勒眼里，这是一整套的浪费，而且工人和老板互相提防，各藏一手。

他决定做一件当时近乎离经叛道的事：把"怎么干活"从工人的脑子里，搬到管理者的手里。他拿着秒表去测每一个动作，把搬生铁拆成一步步，找出最省力的那一套，写成标准，再训练工人照着做。

这件事后来有了个名字，叫科学管理。可比名字更要紧的是，它标志着一个东西的诞生：管理第一次成了一门可以被研究的学问，而不再只是当老板的经验。

泰勒做的这件事，有个更贴切的说法，叫蒸馏——把分散在一个个工人身上、说不清道不明的经验，提炼、浓缩成一份别人能照着用的东西。这个词后面还会反复回来，它是这本书的一条暗线。

一百多年后，我们走到了一个很像的路口。只是这一次，要被蒸馏出来、变成标准的，不再是工人搬铁的动作，而是一整套做事的方法；接手它的，也不再只是人，还有会自己干活的软件。

---

今天我们很容易嘲笑泰勒。拿着秒表掐时间，把人当机器，"泰勒制"几乎成了血汗工厂的代名词。

但这是误读了他。剥开秒表那层容易挨骂的皮，泰勒真正解决的，是工业化时代的头一个大难题：当协作的规模大到没人能全知全能，靠什么让一群人可靠地、一致地把活干好。

他的答案有四条，写在 1911 年那本《科学管理原理》里。为每一个工作环节发展出一门科学，取代凭经验的大概齐。科学地挑选和训练工人，而不是让他们自生自灭。管理者和工人真诚合作，确保工作照科学的方法走。管理者和工人几乎均分工作和责任，管理者管方法和计划，工人管执行。

泰勒自己有一句话：管理的首要目标，是让雇主获得最大的繁荣，同时让每一个雇员也获得最大的繁荣。他的本意不是压榨。他真诚地相信，把方法科学化、把蛋糕做大，老板和工人能一起得利，而不是零和地互相提防。

泰勒真正的贡献，藏在第四条里。他把方法的设计，从工人个人的本事，变成了管理者的职责、组织的资产。在他之前，怎么干是工人脑子里的隐性知识，人走了，知识就走了。在他之后，怎么干被写下来、被标准化、被沉淀成组织能反复用的东西。这件事，比秒表重要一万倍。它是管理作为一门学问的起点。

当然，泰勒的方法有它的边界。它在稳定、可重复、可测量的工作上最灵。工作一旦变得多变、含糊、要靠临场判断，秒表就帮不上忙了。他还有一个乐观的假设：管理者总能提前找到那个最好的方法，把变化当成需要消灭的敌人。这个假设，在今天会遇到麻烦。

从泰勒到今天，中间隔着一百多年，也隔着好几代机器。最早的计算机只会执行写死的指令，你让它做什么它做什么，一步都不会多。后来有了会算概率、能从数据里学规律的模型，它开始能应答、能生成，但你问一句它答一句，答完就停。真正的变化发生在最近这几年：模型被接上了工具、记忆和一个能持续运转的运行环境，于是它从"会应答"变成了"能自己干活"。它能接一个目标，自己拆任务、调工具、一步步往下走，还能在中途改主意。这样的东西，今天有了个名字，叫 agent。本书后面谈的 agent，都是指这种能自己把活干完的软件，不是早年那种只会照着指令走的程序。
---

泰勒那件核心的事——把方法从个体脑子里搬出来、变成可复用的组织资产——在今天不但没过时，反而是让 agent 能干活的前提。

这里先立一个贯穿全书的立场：不管技术成熟到什么地步、AI 聪明到什么程度，管理者先把 agent 当成一个员工来对待。先用管人的那套框架去问问题，再看哪些答案一样、哪些答案不一样。

循着这个立场往下看。一个 agent 要可靠地完成一项工作，恰恰需要泰勒当年做的那一整套：把任务拆解清楚，把标准的操作条件固定下来，选对工具，设好验收的测试。只是这些东西换了名字。泰勒的方法卡、工具、指令、检验，今天叫提示词、工具接口、检索来源、权限、验收测试、升级规则。

一个工人拿到一套烂方法，他会累、会抱怨、会偷偷改良。一个 agent 拿到一套烂方法，会一丝不苟、不知疲倦地重复上千遍。它不会累，不会抱怨，也不会自己纠偏。把工作设计好再交出去，这个泰勒式的责任，在 agent 面前只会更重。

有一点要先说清楚，免得被误会：agent 时代，标准化不是退场了，是比泰勒那时候更进了一步。

泰勒标准化的是动作——这一铲该怎么挥、手往哪放、停几秒。他把动作写进方法卡，交给工人照着做。今天我们把一套做事的方法写成 agent 能直接执行的技能，叫它 Skill。Skill 本质上就是一份 SOP，一份标准作业流程，只不过它不再是给人读的纸，而是机器能读、能直接跑的东西。标准化这件事没变，变的是它的载体：从人照着做的动作，变成机器照着跑的流程。

测试也一样。泰勒拿着秒表一遍遍测哪套动作最省力，这就是测试。今天 agent 的评测，是更快、更密的测试——同一个目标，agent 跑出几条不同的路径，哪条更好，当场跑一遍评测就见分晓；改一次提示词、换一个工具，就能把整套评测重跑一遍。泰勒一天测几回，今天一分钟测几十回。测试不但没少，反而成了家常便饭。

变的是标准化落在哪一层。泰勒把每一个动作都定死，因为那时执行的是人的手，手只会照着教的来。agent 会自己找路，装上 Agent Harness 之后，它能自己生成方法、自己重写计划、调用别的 agent。你把每一步都定死，等于把它会找路这件最值钱的本事废掉。所以要标准化的不再是中间那条路，而是两头，要什么结果、不许越哪些红线、交出来的东西怎么验。中间放开，让 agent 自己找，再用更密的测试兜住它。

Palantir 的 AI FDE 就是这么用的。你用自然语言给它一个目标，它自己决定怎么建数据管道、怎么改结构、怎么配权限。它不照你写死的步骤走，它自己找路，而你守住的是目标、权限和验收。

于是科学管理从动作的科学，变成了委派的科学。泰勒管的是这一铲该怎么挥；今天的管理者，管的是我要什么结果、你不许越过哪些红线、你交出来的东西怎么验。中间那条路怎么走，交给 agent。

泰勒要求管理者设计工作。agent 时代，要求管理者连工人一起设计。因为你面对的不再是一个既定的工人、去教他一套方法。你是在定义一个执行体的边界，它能读什么、写什么、调什么、花多少、什么时候必须停下来问人。你设计的不是方法，是这个数字工人本身。

既然要设计工人，那就得先知道，你要设计的是哪一种工人。Agent 已经分化成了不同的形态。这是第二部的事。

---

落到一张能用的表上。泰勒给每个工序配一张方法卡，写清怎么干。agent 时代，给每个 agent 配一张能力边界卡，写清边界。

| 泰勒的方法卡（管动作） | Agent 的能力边界卡（管边界） |
|----------------------|----------------------------|
| 这一步怎么做 | 要什么结果（不规定怎么做） |
| 用什么工具 | 能调哪些工具、不能碰哪些 |
| 标准工时 | 能花多少（token / 时间 / 钱）的预算上限 |
| 怎么检验合格 | 用什么验收测试、证据是什么 |
| —— | 什么情况必须停下来问人（升级规则） |
| —— | 哪些是绝对禁止的捷径（反目标） |

这张卡的哲学变了。泰勒的卡是照着做，边界卡是别越界。前者把人当执行动作的手，后者把 agent 当会自己找路、但必须待在圈里的执行体。填不满这张卡就上线一个 agent，等于给一个不知疲倦、会自己找路的东西，一把没有护栏的方向盘。

---

泰勒解决了一个工序怎么标准化。他没解决一个更大的问题：为什么会有公司这个东西。为什么这些被标准化的工序，要被塞进一个叫组织的容器里，用层级、部门、汇报线捆在一起，而不是每个工序都在市场上单独交易。

这是下一章的事。而 agent 正在把找人、谈判、监督这些协调的成本压到很低，那个当初把工序捆成公司的理由，正在松动。组织这张图，也正在从一张岗位图，变成一张结果图。
