# 第 7 章　岗位让位于闭环

有一家公司，二十年来只干一件事，把它干成了一门独门本事，它叫帕兰提尔（Palantir）。

它最值钱的资产，是一群被派到客户现场的工程师。它不像别的软件公司那样，把工程师留在总部写代码、再让销售拿去卖，而是把人直接派到客户那里，蹲在客户的分析师、操作员旁边，看他们真实怎么干活，然后就地把软件写出来、接上数据、推上生产。

帕兰提尔真正的精妙，不在派人下去，在它那套角色分工。它把现场的活分给两种人。一种盯着该解决哪个问题、用户到底怎么干活、怎么让人真用起来；另一种盯着快速把能跑的软件建出来。这两种人并肩作战，一个管问题选对没有，一个管东西建出来没有。他们身后还有一群产品工程师，专门把现场反复出现的模式，沉淀成平台的通用能力。

帕兰提尔的交付单元围绕客户问题临时组建。问题解决后，产品工程师会把现场经验沉淀为平台能力，供后续项目复用。

这种项目组织方式，也提供了一个观察 Agent 时代的视角：工作可能围绕完整结果组织，而不是分散在固定岗位之间。

---

巴纳德把组织描述为由共同目的、沟通和贡献意愿维系的协作系统。固定岗位、部门和汇报线，是组织稳定协作的一种方式。

组织要稳定运转，需要明确责任、信息流向和决策位置。岗位把这些安排固定下来：一个人负责哪些工作、向谁汇报、与谁协作。部门、层级和流程也由此形成。

岗位化解决了大规模协作中的重复协调问题。职责固定后，成员不必每次从头商量由谁做什么。组织牺牲了一部分灵活性，换来相对稳定的责任关系。岗位也是这种稳定关系的一种制度安排。

岗位也会把端到端的结果切开。一个客户问题可能先后经过销售、产品、工程和客服；每个岗位完成自己的部分，仍需要跨部门协调才能解决问题。

过去，围绕每个结果临时组建跨职能团队，寻找成员、对齐目标和持续沟通的成本很高。Agent 和协作工具正在改变这笔成本，但并没有让协调本身消失。

---

巴纳德关于共同目的和协作的观点，仍然适用于人和 Agent 共同工作的组织。

在岗位化组织中，成员可能只对岗位指标负责，而没人持续跟进最终结果。若 Agent 能降低跨职能协作的部分成本，组织就可以尝试围绕共同目标组建临时单元。这是对协作系统的一种重新安排。

Agent Harness 可以持续运行并编排任务，降低部分协调成本。管理者可以把人和 Agent 组成围绕同一结果工作的单元，但目标、交接和责任仍需明确。

于是有了帕兰提尔那种人加 agent 的部署小队，也有了一些前沿公司把交付单元做成一个 pod 而非一个工程师的结构，里面有领域操作者、客户工程师、现场工程师、交付负责人、高管发起人，还有一条回流到模型团队的反馈通道。这个单元不对应任何一个传统岗位，它对应一个结果。

一个常见现象是，工作流和职责调整了，正式汇报线却没有同步变化。工作流可以由团队局部调整；汇报线还牵涉预算、编制、职业路径和权责，因此通常变化更慢。两者之间可能出现一段时间的错位。

协作关系仍然需要制度承载，但承载方式可以从固定岗位扩展到围绕结果组建的单元。

---

沿着这个判断继续推，组织的基本原子就该换了。它从岗位，一个稳定的责任包，变成结果单元，一个围绕端到端结果编成的人机闭环。

过去是先有岗位，再把结果切成碎片分给各岗位。现在是先有结果，再围绕它临时编一个人加 agent 的组织阵型，端到端地把它闭环。

结果单元按目标配置成员，可能跨越部门和职能。任务完成后，团队可以解散或转向新任务，现场经验则沉淀到平台。帕兰提尔的部署团队展示了这种做法的一种形态。

这不意味着岗位会立即消失。汇报线、职级和部门还承担预算、职业发展与问责等职能。变化发生在部分工作的组织方式上：团队可以围绕结果重新配置人和 Agent。管理者需要说明这个结果需要哪些判断和执行能力、由谁提供，以及如何验收。单纯把 Agent 加到现有岗位上，未必能解决跨岗位的交接问题。

---

要围绕一个结果编一个单元，而不是往旧岗位上贴 agent，先答这几问。

| 问题 | 要钉死的 |
|------|---------|
| 这个单元对什么结果负责？ | 一个端到端的、可验证的结果，比如把首解率提到八成，而不是笼统的"负责客服" |
| 这个结果要什么阵型？ | 需要哪些人、哪些 agent、哪些技能，按结果配，不按现有编制配 |
| 谁供判断，谁供执行？ | 人守住问题选择、风险判断、组织权威，agent 供执行力 |
| 怎么闭环？ | 结果达成后，经验怎么沉淀（进平台、知识库、技能），阵型怎么重组 |
| 和旧岗位图什么关系？ | 明确这个单元横跨了哪些传统岗位、部门，这些墙就是它要打穿的 |

使用这张卡时，先明确结果，再配置所需的人机团队。这样可以避免只给现有岗位增加 Agent，却没有人对端到端结果负责。

---

结果单元还需要成员能够复用经过验证的工作方法。帕兰提尔将现场形成的一些方法沉淀到平台，供后续团队使用。

岗位时代的标准操作流程主要写给人阅读。Agent 需要可调用、可执行的工作指令。下一章讨论如何把标准化方法设计成既能供人理解，也能供 Agent 使用的能力模块。
