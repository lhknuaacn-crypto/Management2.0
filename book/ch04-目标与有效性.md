# 第 4 章　目标与有效性

2025 年 6 月，Salesforce 的创始人马克·贝尼奥夫在一次采访里说，AI 现在干了公司里三到五成的活。这句话被广泛引用，听起来像是公司一半的工作已经交给了机器。

几个月后，他在另一个场合澄清，工程领域的生产力提升约为三成，工程师仍然不可缺少。

两句话说的不是同一件事：一句估算工作量，另一句谈生产力和岗位需求。

工作量不能直接代表产出价值。Agent 可以生成大量报告、邮件和分析，但这些内容是否解决了问题，还要看结果。

这个问题，六十年前有人就问过，只不过他问的对象是人。

---

彼得·德鲁克研究的是知识工作者。

二十世纪中叶，越来越多的人靠脑子里的知识吃饭，不再靠手上的力气，工程师、分析师、研究员、经理。德鲁克看出这种人有一个泰勒那套办法管不住的毛病：他可以非常聪明、非常专业、非常忙，却什么结果都产不出来。

体力劳动者的产出好量，一天砌了多少砖、装了多少台。知识工作者坐在那儿想了一天，你怎么知道他有没有产出。德鲁克给的答案，到今天还挂在每一本管理教材里：别看忙碌，看贡献。他有一句话，六十年了还被人引用——有效的管理者聚焦于贡献，他从自己的工作中抬起头来，望向目标。

德鲁克面对的是如何衡量知识工作。工程师、分析师和经理的产出，不像砖块那样容易计数。他主张把注意力放在工作对机构的贡献上，而不是一个人看起来有多忙。他也认为，有效性可以通过实践学习，包括管理时间、发挥长处、聚焦要事并作出有效决定。

德鲁克写作时，一份分析报告需要投入较多时间。今天，软件可以用很低的边际成本生成大量内容，工作量和贡献之间的差距因此更难忽略。

---

德鲁克的贡献原则仍然适用于人和 Agent 共同工作的单元，但需要处理新的成本结构。

管理者可以先说明 Agent 要改善什么结果、服务谁、用什么证据验收。单说“处理工单”只描述活动；若目标是把首次解决率从六成提高到八成，并将误判率控制在百分之二以内，验收标准就清楚得多。

同时，生成内容的成本已显著下降，德鲁克时代的产出成本假设不再适用。

大模型接入工具、记忆和持续运行环境后，开始能够连续执行任务。Stripe 的 Minions 就是一个例子：员工从 Slack 分派任务后，它会在隔离的云环境里修改代码、运行测试并提交合并请求，供工程师审查。Stripe 称其可以并行运行多个任务。

Agent 的边际生成成本因此降低。它可以快速产出报告、邮件或工单，但如果结果无人核验、无人采用，这些活动就没有形成相应的贡献，还会增加后续处理工作。

Minions 每周生成一千多个 PR，说明 PR 数量本身不能代表生产力。拆分任务或提交细小改动，都可能推高这个数字。Anthropic 和 OpenAI 的内部研究也提醒，不宜用代码行数、prompt 数、PR 数或 token 消耗衡量绩效。这些指标容易计数，却难以说明判断质量、评测效果或真正的业务进展。

Klarna 曾用“相当于 700 名客服的工作量”描述 AI 处理的对话量。这个数字没有直接衡量服务质量。后来公司承认，过度强调成本影响了服务，并重新增加人工客服。处理量增长，并不保证服务结果改善。

Agent 扩大了活动量，也扩大了管理者核算真实贡献的难度。

---

当 Agent 可以持续运行，组织的瓶颈可能从生产转向验证和接收。管理者既要看它生成了什么，也要确认团队有没有足够时间审查和处理这些结果。

德鲁克教我们给贡献算账。agent 时代要补一句：你要做预算的，不只是机器的执行，还有组织的注意力。

一份报告的生成成本可能很低，但阅读和核验仍要占用人的时间。一百个工单也需要被审查、分派，并处理其中的错误。Agent 生成得越多，下游团队承担的工作也可能越多。

衡量 Agent 的贡献时，还要扣除验证、协调、异常处理和下游注意力成本。一份无人阅读的报告没有形成使用价值；一份需要从头核验的报告，也可能抵消它节省的时间。

绩效评估还要看这个单元是否让组织其他环节更有能力。Agent 的活动量只是起点，最终要看它是否让工作更省时、更可靠。

---

启动人机工作单元前，可以用三个问题检查目标和成本：

| 问题 | 要钉死的东西 |
|------|-------------|
| 贡献给谁？ | 这个单元的产出，让机构里哪个人、哪个环节变得更有能力？说不出受益者，就是在造活动，不是造贡献。 |
| 证据是什么？ | 凭什么说贡献发生了？是业务指标动了（首解率、周期、成本），还是只是跑了很多？活动指标一概不算。 |
| 净账划算吗？ | 产出价值，减去验证、协调、异常、下游注意力，还剩正的吗？算不出净账，就先别放大它的产量。 |

回答不出这些问题时，不宜先扩大 Agent 的产量。否则活动量增长，验证和处理成本也会一起增加。

---

德鲁克假设，贡献这把尺子握在人手里，是人在判断哪个结果值得追求、哪个贡献算数。

Agent 也开始参与目标筛选和任务排序。当它影响组织对“贡献”的定义时，管理者还要决定哪些目标可以由系统提出，哪些必须由人确认。
