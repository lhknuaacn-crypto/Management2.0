# 第 4 章　目标与有效性

2025 年 6 月，Salesforce 的创始人马克·贝尼奥夫在一次采访里说，AI 现在干了公司里三到五成的活。这句话被反复引用，配上耸动的标题，像是一家顶级软件公司的一半工作量已经交给了机器。

几个月后，还是他，在另一个场合把话说清楚了。工程这块，AI 带来的其实是大约三成的生产力提升，而且工程师照样得要，AI 没法自己把他们的活接过去。

同一个人，同一家公司，两句话。头一句讲 AI 干了多少活，第二句讲这些活到底产出了什么。这两句话之间的距离，就是这一章要谈的全部。

干了多少活，和产出了什么，从来是两回事。而 AI 把这两者之间的缝，撑到了前所未有的宽。一个 agent 一天能写一千份报告、发一万封邮件、跑一百个分析。它非常忙。可忙，不等于有贡献。

这个问题，六十年前有人就问过，只不过他问的对象是人。

---

彼得·德鲁克面对的是一个新物种，知识工作者。

二十世纪中叶，越来越多的人靠脑子里的知识吃饭，不再靠手上的力气，工程师、分析师、研究员、经理。德鲁克看出这种人有一个泰勒那套办法管不住的毛病：他可以非常聪明、非常专业、非常忙，却什么结果都产不出来。

体力劳动者的产出好量，一天砌了多少砖、装了多少台。知识工作者坐在那儿想了一天，你怎么知道他有没有产出。德鲁克给的答案，到今天还挂在每一本管理教材里：别看忙碌，看贡献。他有一句话，六十年了还被人引用——有效的管理者聚焦于贡献，他从自己的工作中抬起头来，望向目标。

德鲁克解决的是人类头一回大规模面对看不见的劳动时的难题。当产出不再是一堆砖，而是一个决策、一份判断、一个想法，你靠什么管它。他的答案是，把注意力从这个人有多忙移开，钉在这个人给机构的结果贡献了什么上。这个转向经受了半个世纪的检验。他还留下一句更硬的话：有效性是可以学的。它不是天赋，是一门功夫——知道时间花在哪、聚焦贡献、发挥长处、分清少数要紧事、做管用的决定。

但德鲁克整套办法底下，压着一个他那个年代天经地义的前提：产出是贵的。一个知识工作者写一份分析报告，要搭进去半天。正因为产出贵，忙碌和贡献才不至于差得太离谱——一个人再怎么瞎忙，一天也就产出那么多，你总盯得过来。

今天，产出不贵了。

---

把德鲁克这把看贡献不看忙碌的尺子，拿到人和 agent 的混合单元里，会发现两件事。

头一件，这把尺子不但没坏，还更该用了。管理一个 agent，第一个要问的恰恰是德鲁克式的问题：不问这个模型能做什么，问这个 agent 要贡献什么结果、给谁、拿什么证据、达到什么水准。一个接进来就让它处理工单的 agent，和一个明确要把工单首次解决率从六成提到八成、且误判率不超过百分之二的 agent，是两种完全不同的东西。前者是活动，后者才是贡献。

第二件，德鲁克那个产出昂贵的前提，今天不成立了。他没见过一种能把忙碌变得几乎免费的东西。

这种东西，是最近三年才长出来的。早先的大模型只会应答，你问一句它答一句，答完就停。后来它被接上了工具、记忆和一个能持续运转的环境，从会应答变成了能自己干活。Stripe 内部就有这么一个东西，叫迷你工（Minions）。你从 Slack 丢给它一个任务，它在一个隔离的云环境里自己跑，改代码、跑测试、修 CI，最后开出一个代码合并请求等人 review。它不用你盯着，能同时跑几十个。

于是一件德鲁克没预料到的事发生了：一个 agent 的边际产出成本，趋近于零。它一天能生成一千份报告、发一万封邮件、开一千个工单，活动量近乎无限，而它真实的贡献，可以是负的。

那个每周开出一千多个 PR 的迷你工，看得最清楚。PR 数是活动，不是生产力。一个能靠拆任务灌水、靠小改动虚高的数字，证明不了任何真实产出。别的造 agent 的公司也想明白了同一件事，Anthropic 和 OpenAI 在各自的内部研究里都提醒，别拿代码行数、prompt 数、PR 数、token 消耗来衡量绩效。OpenAI 说得直白，这些数字都好测，却难解读，真正的进展可能卡在判断、算力、评测质量，或者某个根本没被自动化的瓶颈上。

Klarna 那个"AI 替代了 700 个客服"的故事，是同一个陷阱的另一面。那个 700，是一笔工作量等价的账，AI 处理了相当于 700 个全职客服的对话量。可处理了多少对话，和这个服务做没做好，是两码事。后来 Klarna 自己承认，当成本成了压倒一切的评价标准，质量掉了下去，于是又把人请了回来。对话量拉满，贡献却缩了水。

活动可以无限，贡献却有天花板。德鲁克在人身上看到的那道缝，在 agent 身上被撑大了一千倍。

---

把这条线捋到底，新原则几乎自己冒出来。技术让 agent 能无人值守地一直跑，产出趋近于免费，而产出一多，瓶颈就从生产这头，移到了有没有人能验、能接、能信那头。管理者面对的，是一队能无限产出、又把稀缺甩给下游的执行体。

德鲁克教我们给贡献算账。agent 时代要补一句：你要做预算的，不只是机器的执行，还有组织的注意力。

一个 agent 生成一份报告，几乎不花钱。可这份报告一旦生成，就开始耗掉一种真正稀缺的东西——有人得读它、验它、信它，或者驳它。一个 agent 开一百个工单，机器的成本可以忽略，可这一百个工单，得有人去审、去分、去收拾它做错的那些。agent 越能生成，下游的人就越被挤兑。

所以衡量一个 agent 的贡献，不能停在它产出了什么，要算一笔净账：它的产出价值，减去验证成本、协调成本、异常处理成本，再减去它给下游人塞进去的那份认知负荷。一份没人读、或者读了还得从头核一遍的报告，产出为正，贡献为零，甚至为负，因为它偷走了本可以用在别处的注意力。

这把绩效这件事在混合组织里的样子也改了。老问法是这个单元产出了多少，新问法是这个单元让机构的其余部分多有能力了。一个好的 agent，不是最忙的那个，是让它周围的人和系统都变得更省力、更可靠的那个。

---

德鲁克的有效性是一门可学的功夫。到了 agent 时代，这门功夫可以压成三个问题，任何一个人机单元启动前先答这三问。

| 问题 | 要钉死的东西 |
|------|-------------|
| 贡献给谁？ | 这个单元的产出，让机构里哪个人、哪个环节变得更有能力？说不出受益者，就是在造活动，不是造贡献。 |
| 证据是什么？ | 凭什么说贡献发生了？是业务指标动了（首解率、周期、成本），还是只是跑了很多？活动指标一概不算。 |
| 净账划算吗？ | 产出价值，减去验证、协调、异常、下游注意力，还剩正的吗？算不出净账，就先别放大它的产量。 |

这三个问题不长，但它逼你在启动前想清楚德鲁克六十年前就想清楚的那件事，只是换了对象：别被忙碌骗了。一个答不出这三问的 agent，产量越高越危险。

---

德鲁克假设，贡献这把尺子握在人手里，是人在判断哪个结果值得追求、哪个贡献算数。

但 agent 不只是产出得快，它开始能自己判断什么值得做——提出目标、筛方向、决定把力气分给哪个任务。当 agent 开始参与定义什么是贡献这件事本身，德鲁克那把尺子，就不完全握在人手里了。

而要管一个会自己判断、会自己使用工具的执行者，先得弄清它到底是个什么东西。这是下一部的事。
